# Harness findings — 29 Jul 2026

First run of the automated extension test harness, plus the corrections from
Codex's audit of this report (ACCEPTED WITH CORRECTIONS). 17-route API matrix +
a 2-case browser E2E, both against the live tracker.

## Headline: a false-empty-state on transcons (medium)

This is the thing Jeremy saw on SFO→EWR, reproduced on four routes and confirmed
in a real browser. Codex's ruling: a real medium-severity false-empty-state bug,
though **not** a strict data contradiction — the wording matters and is corrected
below.

On a route with **no direct** Starlink flight history — the premium transcons,
which United flies on widebodies/757s that lag on the retrofit — `renderPanel()`
in `extension/content.js` prints its empty state:

> No Starlink history on this route yet.

…and then, on the **next line**, appends a connection row whenever
`/api/plan-route` returns a full-coverage itinerary. Verbatim, from the Phase-2
browser run on live data:

```
🛰️ LAX→EWR · Aug 28
No Starlink history on this route yet.
via MCI (connection)
96%
```

A reader is told there is no Starlink on this route, directly above a 96%
all-legs Starlink estimate via MCI. The four affected routes and their
**all-legs** connection estimates:

| Route | Connection | All-legs estimate |
|---|---|---:|
| SFO→EWR | via GEG+ORD | 55% |
| EWR→SFO | via MCI+LAX | 49% |
| LAX→EWR | via MCI | 96% |
| SFO→BOS | via GEG+ORD | 73% |

Range **49–96%** (an earlier draft of this note said 55–96% — wrong; EWR→SFO is
49%). These are genuine full-trip / all-legs estimates, not single-leg numbers.

**These are proven-genuine empties, not failed calls.** The re-run records the
`predict_route_starlink` status per route: all four transcons returned HTTP 200
with a parseable body listing zero direct flights (`dirOk ✓` in the route
matrix). So "no direct history" is a real state here, and the connection is real
— the defect is purely that the copy asserts more than "no *direct-flight*
history".

## Root cause runs deeper than copy (the state-model bug)

Codex's key structural finding, and it's correct: the extension cannot tell
"direct history loaded and is empty" apart from "the direct-history request
failed". In `extension/bg.js` (~line 233) the route response is deemed `ok` when
`flights.length > 0 || itins.length > 0 || …`, so a **failed** direct-history
fetch collapses to `flights: []` while a **successful** connection fetch still
makes the overall response succeed. `content.js` (~line 972) then renders "No
Starlink history…". So on a direct-history failure the panel asserts an absence
it cannot prove.

A copy change alone papers over this. The honest fix pairs new copy with a state
flag that carries whether the direct-history call actually succeeded.

## Codex's approved copy/state rule (design sign-off)

Keyed on four states. To ship as part of v2.2.0, with Jeremy's go:

- **Direct history loaded, empty, connection available:**
  "No direct-flight Starlink history yet. Connection estimate below."
- **Connection row label:** "via MCI · all-legs estimate — 96%"
- **Direct history loaded, empty, no connection:**
  "No direct-flight Starlink history for this route yet."
- **Direct-history request failed / unparseable:**
  "Direct-flight history unavailable right now."
- **Direct rows present:** show no empty-state copy.

Do **not** use "No direct Starlink flight" — history does not prove flight
availability. Do **not** use "best connection" unless the row is actually changed
to select the highest joint-probability itinerary (today it takes the first
full-coverage one, not the best).

## What is solid — with scope stated (Codex's correction)

- **Endpoint parity: 0 differences across 26 comparisons** (25 unique direct
  flights, top-3 per route). The united.com panel and the Google Flights / Navan
  chips agree for the flights sampled. It does **not** validate the empty
  transcons (no direct flights to compare) or the connection math.
- **Roster cross-check: clean on the firm-tail sample** — UA1's N81107 (tracker
  "no") is not in our roster; UA1596's N73275 and UA5693's N85369 (tracker
  "yes") are both in it. This is a handful of firm tails (published ~48h out),
  **not** a reconciliation of the full 485-tail roster.
- **Normal path displays correctly.** SFO→DEN renders a ranked direct list and
  the page's "United 1596" text gets a live `★ 🛰️ 68%` badge.
- **Extension loads clean** unpacked in Chrome for Testing — SW registers, zero
  console errors.

## Lower-confidence / watch items

- **`plan-route` returned 0 itineraries once, mid-matrix, then 16/16 full on
  controlled repeats.** Called a transient (rate-limit or timeout), not a
  systemic flip. It matters because the extension uses `Promise.allSettled` with
  **no retry** on `plan-route`: on that blip an empty-direct route loses even its
  connection row. A single retry would remove the worst case.
- **`airlines.js` vs site roster drift:** bundled `airlines.js` says United
  481/1808; `wifiodds united/data.json` is at 485 (updated 2026-07-29). Small,
  expected snapshot drift; worth a periodic re-sync.
